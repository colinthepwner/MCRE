Introduction

A mod is a .zip file. Turn this one on in the Mods tab to see what a mod can do:
  - it changes how the game looks, sounds and reads: dirt turns purple, the apple turns gold,
    menu buttons pop instead of click, and both get new names;
  - it adds blocks, items and recipes: Example Ore underground (and in the Nether), which
    drops Example Gems (2 dirt make 2 as well), the glowing Example
    Block, the Example Counter (gem + planks), the slippery, falling Example Slide (gem +
    sand) and the Example Wand (gem + stick);
  - and scripts/main.js makes them do things: the Counter opens a menu, the Wand tells you
    what a block is, /example is a command, and K shows your coordinates.

Presets

Small mods to start from, one thing each - using the game's own textures, so they're all JSON and script. Download one, unzip it, change the "id" in manifest.json, then open the folder in the Mods tab (Add mod > Open a folder) and press Reload as you change it. They're kept up to date with the game.

In the game: Add mod > Browse mods > Sources, add https://colinthepwner.github.io/MCRE/modding/presets/index.json to install them from there.

What's inside

manifest.json         Who the mod is. Required:
                        "id": "example"        (lower-case letters, digits, . _ - ; must be unique)
                        "devices": "any"       what it's made for: "any", "computer" or "mobile".
                                               A label, not a lock - players see it in the Mods
                                               tab (and get a heads-up if they're on the other
                                               kind), and mod lists can show it too ("devices")
                      Shown in the Mods tab: "name", "version", "author", "description".
                      A mod isn't made for one version of the game: it keeps working as the
                      game updates. ("format" and "type" are fine to leave in; they're ignored.)
                      "dependencies": ["other_mod", {"id": "nice_to_have", "optional": true}]
                        other mods this one needs: they're turned on with it and loaded first.
                        One that's missing shows in the Mods tab.
                      "settings": what players can change in the Mods tab (Settings) or with
                        /modsettings <id> in a world - each player's own:
                        {"id": "sparkle", "name": "Sparkles", "type": "toggle", "default": true}
                        {"id": "count", "type": "slider", "min": 0, "max": 20, "step": 1, "default": 6}
                        {"id": "count", "type": "number", "min": 0, "max": 1000, "default": 6}
                        {"id": "mode", "type": "choice", "options": ["easy", "hard"], "default": "easy"}
                        {"id": "motd", "type": "text", "default": "Hello"}
                        {"id": "menu_key", "name": "Open the menu", "type": "key", "default": "O"}
                          - a key the player picks. It's listed in Options > Controls > Key
                          Bindings under your mod's name, with the game's own keys (as in
                          Java), and in your Settings; it's a key code - "KeyO", "Digit1", "F8",
                          "Space". Scripts hear it: client.on("keybind", e => e.id === "menu_key"
                          && e.down ...) - whatever the player bound it to
                        ("description" on any: a line under it). Scripts read them with
                        mod.settings.get("sparkle") and hear changes: mod.on("settings").
pack.png              The icon in the Mods tab (64x64 looks good).

textures/blocks/<name>.png    Replaces one block texture.
textures/items/<name>.png     Replaces one item texture.
                      The names are in texture_names.txt (they're Minecraft Java Edition's
                      names, so textures from Java packs drop straight in). Any texture can also
                      be named by its number: textures/blocks/cell_<number>.png.
                      16x16 pixels; bigger pictures are shrunk to fit. For animated strips
                      only the first frame is used.

images/<path>.png     Replaces one of the game's picture files whole, same path as the game's
                      (e.g. images/mob/zombie.png, images/gui/gui.png, images/terrain.png).

sounds/<group>/<name><number>.ogg
                      Replaces the sound "<group>.<name>" - every variant of it. This pack's
                      sounds/random/click.ogg replaces "random.click" (menu buttons).
                      Several files (click1.ogg, click2.ogg...) play at random.

lang/en_US.lang       Lines of key=value that replace the game's text, e.g.
                      tile.dirt.name=Example Dirt

New blocks, items and recipes

blocks/<name>.json    A new block, called "<mod id>:<name>" (this one: example:example_block).
                      Everything is optional; these are shortcuts, and scripts do the rest.
                        "name"        what it's called in the game
                        "texture"     a texture name: one of this mod's textures/blocks/<n>.png,
                                      or any of the game's (texture_names.txt). Different faces:
                                      {"top": "a", "bottom": "b", "side": "c"} (also "all",
                                      "up", "down", "north", "south", "east", "west")
                        "hardness"    how long it takes to break (stone is 1.5, dirt 0.5;
                                      -1 can't be broken)
                        "tool"        "pickaxe", "axe", "shovel" or "none"
                        "sound"       stone, wood, gravel, grass, metal, glass, cloth or sand
                        "light"       how much light it gives, 0-15 (a torch is 14)
                        "transparent" true for blocks you can see through (glass-like)
                        "drops"       "self" (default), "none", or an item; "drop_count"
                        "shape"       "cube" (default), "slab", "top_slab", "carpet", "layer",
                                      "plate", "path", "cactus", "post", "pillar", "table",
                                      "button", "cross" (drawn like a flower), or your own box in
                                      pixels: [x1, y1, z1, x2, y2, z2], each 0-16
                                      (a slab is [0, 0, 0, 16, 8, 16])
                        "collision"   false: players and mobs walk through it
                        "gravity"     true: falls like sand
                        "friction"    0.6 normal, 0.98 like ice ("slippery": true is ice)
                        "flammable"   true: catches fire and burns like wood
                        "scripted"    true: using it does nothing else - your script's "use"
                                      event decides (and it never places a block against it);
                                      its world.scheduleTick ticks reach the script too
items/<name>.json     A new item, "<mod id>:<name>".
                        "name", "texture" (textures/items/<n>.png or the game's),
                        "stack" (1-64), "food" (hunger points it fills, or
                        {"hunger": 4, "saturation": 0.6}), "scripted" (using it on a block does
                        nothing else - your script's "useItemOn" decides)
                        "tool"        "pickaxe", "axe", "shovel", "hoe", "sword" or "shears",
                                      or {"type": "pickaxe", "tier": "iron", "speed": 6,
                                      "durability": 250, "damage": 4} - the tier (wood, stone,
                                      iron, diamond, gold) sets what it can mine and the rest's
                                      defaults
                        "armor"       {"slot": "head" | "chest" | "legs" | "feet",
                                       "protection": 3, "durability": 250, "model": "iron"
                                       (leather, chain, iron, gold, diamond: its worn look), or
                                       "texture": a Java armour layer picture in the mod
                                       ("texture_legs" for the leggings' layer)}
                        "effects"     [{"effect": "speed", "seconds": 30, "level": 1,
                                       "chance": 1}] - when eaten (food), or on what it hits
                                      (throwable). Effects: speed, slowness, haste,
                                      mining_fatigue, strength, instant_health, instant_damage,
                                      jump_boost, nausea, regeneration, resistance,
                                      fire_resistance, water_breathing, invisibility,
                                      blindness, night_vision, hunger, weakness, poison, wither
                        "always_edible" true: eaten even when not hungry
                        "throwable"   true or {"damage": 2, "speed": 1.5, "gravity": 0.03} -
                                      thrown like a snowball; scripts hear where it landed:
                                      mod.on("hit", {item, x, y, z, entity, player})
                        "ranged"      {"ammo": "minecraft:arrow", "power": 1, "durability":
                                      384} - drawn and shot like a bow; the ammo can be an
                                      arrow or one of your throwable items
                        "damage"      what a hit with it does (a club...)
                        "ore"         makes it generate in new chunks, like the game's ores:
                                      {"vein_size": 8, "veins_per_chunk": 8, "min_y": 1,
                                       "max_y": 64, "dimension": "overworld", "replace":
                                       ["minecraft:stone"]} - everything optional ("ore": {} is
                                      iron-like); veins_per_chunk below 1 is a chance (0.25:
                                      one vein in every fourth chunk); dimension "overworld",
                                      "nether" (replaces netherrack), "end" (end stone) or
                                      "any"; a list of these for several kinds of veins
worldgen/<name>.json  The same, for any block - this mod's, another mod's or the game's own:
                        {"type": "ore", "block": "minecraft:diamond_ore", "veins_per_chunk": 2,
                         "max_y": 16}
                      Only chunks generated from now on get them: explore somewhere new.
recipes/<name>.json   {"type": "shaped", "pattern": ["##", "##"], "key": {"#": item},
                       "result": item, "count": 1}
                      {"type": "shapeless", "ingredients": [item, item], "result": item}
                      {"type": "smelting", "input": item, "result": item}
                      An item is "<name>" (this mod's), "<mod id>:<name>" (another mod's) or
                      "minecraft:<name>" (the game's, Java names like minecraft:iron_ingot;
                      add ":<number>" for a variant, e.g. minecraft:wool:14).
Textures for new things are 16x16; the game makes room for as many as your device can hold.

Block models

models/block/<name>.json  A Java block model - exactly what Blockbench exports ("Java Block/Item"):
                       {"textures": {"side": "block/stone", "gem": "example:block/example_block"},
                        "elements": [{"from": [0, 0, 0], "to": [16, 8, 16],
                          "rotation": {"origin": [8, 8, 8], "axis": "y", "angle": 22.5},
                          "faces": {"north": {"uv": [0, 8, 16, 16], "texture": "#side",
                                              "cullface": "north", "rotation": 90}, ...}}]}
                       Any number of boxes, turned -45 to 45 degrees, each face its own texture,
                       uv and rotation; "parent" works with your own models or the usual ones
                       (block/cube_all, cube_column, cube_bottom_top, orientable, cross, slab...).
                       Textures: "<mod id>:block/<name>" is your textures/blocks/<name>.png;
                       "block/<name>" or "minecraft:block/<name>" the game's (newer names like
                       oak_planks work too).
                       Use it from a block: "model": "block/<name>" - or name the model like the
                       block and leave it out. "rotate": "horizontal" turns the block to face
                       whoever places it (a Java blockstates/<name>.json with facing=... variants
                       does the same). Light passes through a block with a model; it can be
                       walked on where the model is (or give "shape" a box for its collision).
                       See example_pedestal and example_chair. A Java mod's assets/<id>/models,
                       textures and blockstates folders work as they are.
models/item/<name>.json   An item model with "parent": "item/generated" gives an item its
                       "layer0" texture.
Every world remembers its mod blocks: open it without the mod and they stay as purple-and-black
placeholders until you turn the mod back on.

Scripts

scripts/<anything>.js  JavaScript that makes your mod do things. scripts/main.js in this mod is
                       a full example; read it alongside this.

Write your script once. It runs on every device in the game - yours, and everyone who joins you -
and the game sorts out where each thing happens:
  - World events (mod.on) fire once, where the world is, never once per player.
  - world.* and players.* work from anywhere; the game sends them where they need to go.
  - Anything aimed at a player (a menu, items, teleporting, healing, a message) reaches that
    player, whichever device they're on.
  - client.* is "this device": its screen, its keys, its sounds, its own player.
In single player it's all one device, and the same script just works.

Names: a block or item is "<mod id>:<name>", "minecraft:<java name>" (e.g. minecraft:stone),
"air", or just "<name>" for your own mod's. A player is {id, name, x, y, z, health}; pass it
(or its id) wherever a player goes.

mod.on(event, function (e) { ... })          where the world is
Every event has the same shape: a block is e.block, e.data, e.x, e.y, e.z; an item is e.item,
e.data, e.count; a creature is e.entity {id, type ("minecraft:zombie"), x, y, z, health}; and
whoever did it is e.player.
  "start" / "stop"     the world opened / closed
  "join" / "leave"     a player joined / left your game
  "respawn"            a player came back after dying
  "use"                any block was used (right-clicked)  block, player
  "place" / "break"    any block was placed / broken       block, player
  "step"               a player walked onto a block        block, player
  "tick"               a scripted block's world.scheduleTick came (block)
  "useItem"            any item was used in the air        item, player
  "useItemOn"          ... used on a block                 item, x, y, z, face, player
  "eat" / "craft"      a player ate / crafted something    item, player
  "smelt"              a furnace finished something        item, x, y, z
  "attack"/"interact"  a player hit / right-clicked a creature   entity, player
  "hurt"               a creature (or player) was hurt     entity, damage, source
  "death"              ... died                            entity, source, player (the killer, or
                                                           the player who died)
  "spawn"              a creature appeared                 entity
  "chat"               a player said something             text, player
  "explode"            an explosion                        x, y, z, power
  "weather"            rain / thunder started or stopped   raining, thundering
  "structure"          a scripted structure generated      name, x, y, z, rotation, size
  "gametick"           every game tick (20 a second)
  "gui"                a button in a menu you opened:       e.gui, e.id, e.action ("click",
                       "submit" - Enter in a text box - or "close"), e.values (text boxes), e.player
  "message"            client.send from a device:           e.data, e.player
mod.command(name, function (c) { ... }, options)
                                             /name typed in chat: c.player, c.args, c.text,
                                             c.isHost, c.isOp. options (all optional):
                                             {permission: "host" (only the world's owner),
                                             "op" (operators - see players.isOp) or
                                             "everyone", description, usage} - /help lists them
mod.send(player or "all", data)              to client.on("message") on that player's device
mod.settings.get(id)  mod.settings.all()     this mod's settings (see manifest.json "settings");
mod.settings.set(id, value)                  where the world is: the host's; client code: that
                                             player's. mod.on("settings") / client.on("settings"):
                                             changed, e.values

world.setBlock(x, y, z, block, data)         world.setData(x, y, z, data)
world.getBlock(x, y, z)                      -> a Promise of {block, data}
world.scheduleTick(x, y, z, ticks)           a "tick" event for a scripted block later
world.spawnItem(x, y, z, item, count)        world.explode(x, y, z, power, fire)
world.time()  -> a Promise of the time       world.setTime(t)      (a day is world.DAY: 19200
                                             ticks, from sunrise; Java's is 24000)
world.timeOfDay()                            -> a Promise of {day, ticks, hour (Java's: 0 is
                                             sunrise, 6 noon), clock "12:00", night}
world.setTimeOfDay(when, next)               "sunrise", "day", "noon", "sunset", "night",
                                             "midnight" or a Java time (0-23999): that time
                                             today - next: true, the next one
world.weather() -> {raining, thundering}     world.setWeather("clear" | "rain" | "thunder",

                                             own weather would last
world.difficulty() -> 0-3                    world.setDifficulty(0-3 or "peaceful", "easy",
                                             "normal", "hard") - the host's own setting
world.sound(name, x, y, z, volume, pitch)    heard by everyone nearby (e.g. "random.pop")
world.container(x, y, z)                     -> a Promise of a chest's (furnace's, hopper's...)
                                             slots: [{item, count, data} or null], or null
world.setSlot(x, y, z, slot, item, count)    put items in a container's slot (item null: empty)
world.fillLoot(x, y, z, table)               fill a container from a loot table

world.spawnEntity(type, x, y, z)             -> a Promise of the new creature's id: one of

Items as stacks: {item, count, data} - and, all optional, what makes a stack special:
  name: "Excalibur", lore: ["a line", "another"], enchantments: [{id: "sharpness", level: 5}]
  (Java's names: protection, fire_protection, feather_falling, blast_protection,
  projectile_protection, respiration, aqua_affinity, thorns, sharpness, smite,
  bane_of_arthropods, knockback, fire_aspect, looting, efficiency, silk_touch, unbreaking,
  fortune, power, punch, flame, infinity - or their numbers), unbreakable: true (it never
  wears), tag: anything of your own (kept on the stack; stacks only merge when it matches).
  Give one anywhere an item goes - players.give(player, {item: "minecraft:diamond_sword",
  name: "Excalibur", enchantments: [{id: "sharpness", level: 5}]}), players.setSlot,
  world.setSlot, world.spawnItem, client.setHeld... - and stacks you read (players.inventory,
  world.container, events) carry them too. Saved with the world as Java saves them.

gui.open(player, menu)  gui.close(player)    a menu on that player's screen:
  {id: "my_menu", title: "Title", width: 380, elements: [
    {type: "text", text: "Hello", color: "#ffcc00"},
    {type: "button", id: "ok", text: "OK", color: "#3a7a3a"},
    {type: "input", id: "name", placeholder: "Your name", value: ""},
    {type: "row", elements: [ ...side by side... ]},
    {type: "divider"},
    {type: "slots", id: "in", count: 9, columns: 9, items: [{item: "minecraft:coal", count: 4}],
     put: true, take: true, accept: ["minecraft:coal"], keep: false},
    {type: "inventory"}
  ]}
  Open it again with the same id to update it.
  Item slots work like a chest: click to pick up, click to put down, right-click for half / one,
  shift-click to move across. Every change is a "gui" event with action "slot" (e.id: which
  slots, e.index: which one), and every gui event has e.slots: {in: [stacks or null]}. "put":
  false makes an output slot; "accept" lists the only items that fit. Leave "items" out when you
  update an open menu to keep what's in the slots. When the menu closes, what's left in slots the
  player can put into goes back to them - unless "keep": true (then e.slots in the "close" event
  is yours to keep, e.g. in storage: see the Gem Bag in scripts/main.js).
  Phones and computers: nothing to do - the same menu is drawn for the device it's on (bigger
  slots and buttons on a touch screen; tap = click, a long press = shift-click, or "put one"
  while holding a stack).
  Designing it yourself, still drawn by the game:
    "style": {"background": "#203040" or "textures/gui/bg.png", "border": "#8af", "color": text,
              "title": title colour, "accent": buttons, "radius": 6, "font": "pixel" | "sans"}
    {type: "image", src: "textures/gui/logo.png" (or item: "minecraft:diamond"), width: 64}
    {type: "grid", columns: 3, elements: [...]}   as many columns as fit, up to 3
    buttons: "icon" (an item or a picture), "textColor"; text: "size", "align", "bold"
  More elements:
    {type: "items", id: "pick", items: [...stacks or names...], columns: 9, rows: 5}
       an item picker: pages of item pictures with their names as tooltips; a click is a "gui"
       event, action "click", with e.index, e.item and e.button ("left" / "right"), e.shift.
       counts: true shows stack sizes, frame: false drops the slot frames.
    {type: "input", ..., live: true}   a "gui" event, action "input", for every change
  Panels - beside the game, not over it: add modal: false (and position: {left | right, top |
  bottom}, width, height in pixels). No dimmed screen, the game keeps the mouse and keys
  everywhere else, several can be open at once, Esc doesn't close them, and hidden: true keeps
  one without showing it. client.on("screen") tells you where the game's inventory window is,
  to put one beside it. client.gui.close(id) closes one. The game's close X always stays on
  top: a panel over it gets a hole there (client.screen().close says where it is).
  All the way - your own page: gui.open(player, {id: "shop", html: "gui/shop.html",
  data: {...}}). gui/shop.html (with its .css, .js, pictures and fonts next to it in gui/) is
  shown in a frame of its own: it can't reach the internet or the rest of the game, only your
  script, through window.mcre - mcre.data (what gui.open sent), mcre.send(x) (-> mod.on("gui",
  {action: "message", data: x})), mcre.on(function (data) {...}) (gui.open again with the same
  id: new data, the page stays), mcre.close(), and mcre.touch (true on a touch screen: lay it
  out as you like). It can show the game's items and pictures too: mcre.icons(items) -> a
  Promise of [{item, data, name, max, rarity, category, icon (a picture URL)...}], and
  mcre.asset("font/default8.png") -> one of the game's own pictures. As a panel (modal: false)
  covering the screen, mcre.area([{x, y, width, height}...]) says which parts of the page are
  yours - the game gets the mouse everywhere else.

storage.get(key)  storage.set(key, value)  storage.all()

Structures

worldgen/<name>.json  {"type": "structure", ...} - something built into new chunks:
                        "layers"      the blocks, bottom layer first; each layer is rows from
                                      north to south, each row a character per block west to
                                      east: " " keeps what's there, "." is air, anything else is
                                      looked up in "key" ({"#": "minecraft:cobblestone", ...})
                        "file"        instead of layers: a schematic in the mod - MCEdit / WorldEdit
                                      .schematic, Sponge .schem or a structure block's .nbt
                        "placement"   "surface" (default: on the ground), "underground" or
                                      "anywhere" (between "min_y" and "max_y")
                        "y_offset"    up or down from the ground (-1 sinks the bottom layer in)
                        "on"          what the ground must be, e.g. ["minecraft:sand"]
                        "chance"      per chunk (0.02: one chunk in fifty)
                        "rotate"      turn it randomly (default: yes for layers, no for files -
                                      stairs, doors and torches don't turn with it)
                        "dimension"   "overworld" (default), "nether", "end" or "any"
                        "scripted"    true: mod.on("structure") tells your script where it went
                        "loot"        fill every chest (and other container) in it from a loot
                                      table; or one at a time in "key":
                                      {"C": {"block": "minecraft:chest", "loot": "chests/hut"}}
                                      or {"block": "minecraft:chest", "items": [{"slot": 13,
                                      "item": "minecraft:diamond", "count": 2}]}
                        "loot_tables" for files: {"minecraft:chests/x": "my_table"} swaps a table a
                                      schematic's chest names for one of yours
                        "biomes"      only in these biomes, e.g. ["desert", "plains"] (ores
                                      take "biomes" too)
worldgen/<name>.json  {"type": "tree", ...} - trees in new chunks:
                        "log", "leaves" any blocks (default the game's oak; "leaves": false
                                      for none)
                        "shape"       "oak" (default), "spruce", "round", "bush" or "column"
                        "height"      [min, max] trunk height
                        "per_chunk"   how many (0.1: one chunk in ten)
                        "on"          what it grows on (default grass and dirt)
                        "biomes", "dimension"
worldgen/<name>.json  {"type": "plant", "block": "example_flower", ...} - flowers, grass,
                      mushrooms... scattered in patches on the ground: "patches" per chunk,
                      "tries" per patch, "on", "biomes", "dimension", "height": [min y, max y]
Biomes: rainforest, swampland, seasonal_forest, forest, savanna, shrubland, taiga, desert,
plains, ice_desert, tundra (Java names like "jungle", "swamp" or "snowy_tundra" work too).
worldgen/<name>.schematic (or .schem / .nbt) on its own works too, with the defaults. Chests in
schematics keep their items, and their loot tables (the game has stand-ins for Java's chest
tables: minecraft:chests/simple_dungeon, village_blacksmith, abandoned_mineshaft, desert_pyramid,
jungle_temple, stronghold_corridor, spawn_bonus_chest, nether_bridge).
Up to 64 x 128 x 64 blocks. Newer files' blocks are matched to the nearest this game has.

Creatures

mobs/<name>.json      A new creature, "<mod id>:<name>":
                        "name"        what it's called
                        "model"       its model: a Bedrock geometry file (.geo.json - Blockbench's
                                      "Bedrock Entity" / File > Export > Bedrock Geometry) or an
                                      OptiFine CEM model (.jem) anywhere in the mod
                        "texture"     its picture (any size; box UVs as Blockbench lays them out),
                                      or one of the game's: "minecraft:mob/pig.png"
                        "behaviour"   "passive" (wanders, runs when hit, breeds), "hostile" (hunts
                                      the nearest player), "neutral" (fights back only),
                                      "flying" (drifts around in the air) or "swimming" (in water)
                        "health", "damage" (hostile / neutral), "speed" (a pig's is 0.25),
                        "size": [width, height] in blocks, "scale" (draws it bigger or smaller)
                        "drops"       [{"item": "...", "count": [min, max], "chance": 0.5}], or
                        "loot"        a loot table
                        "xp"          experience when killed
                        "breed"       an item that makes two of them breed (passive)
                        "burns_in_daylight", "fire_immune"
                        "sounds"      {"ambient": "mob.pig", "hurt": ..., "death": ...}
                        "spawn"       where they appear by themselves - a list of
                                      {"dimension": "overworld", "light": [min, max] (0-15),
                                       "height": [min, max], "on": ["minecraft:grass"],
                                       "biomes": ["plains", "forest"], "weight": 10,
                                       "group": [min, max]}
                        "egg"         [colour, colour]: its spawn egg's colours (an egg is made for
                                      every creature; false for none)
                        "animations"  {"<part>": "head" | "leg" | "arm" | "wing" | "tail" | "none"}
                                      - parts move by their names otherwise: "head" looks around,
                                      "leg..." / "arm..." swing as it walks, "wing..." flap,
                                      "tail..." sways
                      Scripts see it in every creature event (spawn, hurt, death, attack,
                      interact) as e.entity.type "example:example_critter", and
                      world.spawnEntity("example_critter", x, y, z) makes one.
                      See example_critter: it breeds with Example Gems.

Rules

Scripts hear about things after they happen, so they can't stop them. Rules can: the game checks
them at the moment something happens.
rules/<name>.json     {"no_break": [blocks], "no_place": [blocks], "no_use": [blocks],
                       "no_damage": [{"entity": "minecraft:player", "cause": "fall"}],
                       "pvp": false, "explosions_break_blocks": false,
                       "explosion_proof": [blocks], "fire_spreads": false,
                       "no_spawn": ["minecraft:creeper"]}
                      Blocks can be "*" (any). Creatures: "minecraft:player", "minecraft:pig",
                      "<mod id>:<name>", or "*". Causes: any, fall, fire, lava, drown, explosion,
                      attack, projectile, magic, void, suffocation, other. "no_damage": ["fall"]
                      (just causes) means players.
                      Add "area": [x1, y1, z1, x2, y2, z2] (a box of blocks) and / or
                      "dimension" to limit them; {"rules": [{...}, {...}]} for several areas.
                      Block rules leave players in creative mode alone - "creative": true
                      includes them.
In a block: "explosion_proof": true. In a creature: "immune": ["fall", "fire"].
From a script: world.setRules(id, {...}) turns a set of rules on (the same form; the same id
replaces it, null turns it off) - e.g. protect an arena while a game runs. See /example protect.

Loot tables

loot_tables/<path>.json  A loot table called "<mod id>:<path>" (this mod's chests/shrine.json is
                       example:chests/shrine). Java's format works as it is:
                         {"pools": [{"rolls": {"min": 2, "max": 4}, "entries": [
                           {"type": "minecraft:item", "name": "minecraft:diamond", "weight": 2,
                            "functions": [{"function": "minecraft:set_count",
                                           "count": {"min": 1, "max": 3}}]},
                           {"type": "minecraft:empty", "weight": 5},
                           {"type": "minecraft:loot_table", "name": "another_table"}]}]}
                       (set_count and set_data are used; other functions are ignored.) Or short:
                         {"rolls": [1, 3], "items": [{"item": "minecraft:apple",
                          "count": [1, 4], "weight": 3}], "empty": 2}
                       A Java data pack's data/<namespace>/loot_tables/... files work too.
Use them in blocks ("loot": "my_table" drops from the table instead of "drops"), in structures
(above) and from scripts (world.fillLoot, dropLoot, rollLoot).

Order

Mods higher in the list win when two change the same thing. A mod you add goes on top.

Making a mod

Start from this one: Download it from the Mods tab, unzip it, change it.
  - Open the folder, not a .zip, while you work: Add mod -> Open a folder (Chrome and Edge).
    The game reads it straight from your disk. Change a file, then press Reload in the Mods
    tab - or type /reload in a world to reload without leaving it (new blocks, textures,
    recipes and scripts all come in; scripts start again; players who joined you keep the
    old version until they join again). Download on a folder's row makes the .zip to share. (Other browsers: Add mod the .zip again - the same id, name and author
    replace the old copy.)
  - Problems: anything in a mod the game can't use - a recipe with an unknown item, a texture
    that isn't there, broken JSON, a script error with its file and line - is listed in the
    mod's panel in the Mods tab, and counted on its row.
  - Autocomplete: types/mcre.d.ts describes the scripting API and jsconfig.json points your
    editor at it. Open the mod's folder in VS Code (or any editor that reads TypeScript
    types) and mod., world., players. ... complete as you type, with their notes.

Sharing a mod

Add mod -> Browse mods lists mods from mod lists and installs them (with what they need).
A mod list is one JSON file anyone can put online (GitHub Pages works):
  {"name": "My mods", "mods": [{"id": "example", "name": "Example Pack", "author": "you",
    "version": "1.0", "devices": "any", "description": "...", "url": "example.zip", "icon": "example.png",
    "tags": ["blocks"], "dependencies": [], "sha256": "(optional: the .zip's SHA-256)"}]}
"url" and "icon" can be relative to the list. Players add a list under Sources by its
address - or paste the address of a .zip there to install just that mod. A newer "version"
in a list shows an Update button.

Old Pocket Edition mods (ModPE)

BlockLauncher's ModPE scripts work: Add mod -> choose the .js (or a .modpkg). Their blocks, items,
food, armour, recipes and hooks (useItem, destroyBlock, modTick, procCmd, attackHook, deathHook,
chatHook...) run as they did on a phone, with Pocket Edition's ids and texture names. Their
menus (Android buttons, panels, text boxes, checkboxes, sliders, dialogs, toasts) are drawn
by the game, for touch and mouse alike - with a mouse, M frees the cursor for a mod's buttons
while playing. ModPE scripts run where the world is (single player, or the host).

Java resource packs

A Java Edition resource pack .zip (with pack.mcmeta) can be added as it is: its block and item
textures, sounds and en_us.lang lines are used.

Types (mcre.d.ts)

Every script's API, for editors that read TypeScript types (VS Code...): put it next to your scripts with a jsconfig.json and mod., world.... complete as you type. Download mcre.d.ts

// Minecraft RE - mod scripting API, for editors (VS Code and others read this file and complete
// the API as you type). Keep it next to your scripts: this mod's jsconfig.json points the editor
// at types/*.d.ts and scripts/*.js. Nothing here runs - it only describes what the game gives
// every script: mod, world, players, gui, storage, client and log.

/** A block or item: "<mod id>:<name>", "minecraft:<java name>" (e.g. "minecraft:stone"),
 *  "air", or just "<name>" for your own mod's. Add ":<data>" for a variant ("minecraft:wool:14"). */
type Name = string;

/** A player. Pass it (or its id) wherever a player goes. */
interface Player {
  id: number;
  name: string;
  /** Feet position. */
  x: number; y: number; z: number;
  health: number;
}

/** A creature (or other entity) in an event. */
interface Creature {
  id: number;
  /** "minecraft:zombie", "<mod id>:<name>" for a mod's own creature, ... */
  type: string;
  x: number; y: number; z: number;
  health?: number;
  /** Set when the creature is a player. */
  name?: string;
}

/** world.entity(): a creature in detail. */
interface CreatureDetail extends Creature {
  yaw: number; pitch: number;
  motion: [number, number, number];
  onGround: boolean;
  /** Ticks of fire left. */
  fire: number;
  maxHealth?: number;
  /** The creature it's going for (0: none). */
  target?: number;
  effects?: { effect: string; seconds: number; level: number }[];
}

/** Everything an event can carry. Which fields are set depends on the event (see mod.on). */
interface GameEvent {
  /** The event's name. */
  t: string;
  /** A block: its name, data value and position. */
  block?: Name; data?: number; x?: number; y?: number; z?: number;
  /** An item: its name and how many. */
  item?: Name; count?: number;
  /** The face of a block an item was used on (0 down, 1 up, 2 north, 3 south, 4 west, 5 east). */
  face?: number;
  /** Whoever did it. */
  player?: Player;
  /** The creature it happened to, and (hurt / death) what did it. */
  entity?: Creature; source?: Creature | null;
  damage?: number;
  /** "chat" */
  text?: string;
  /** "explode" */
  power?: number;
  /** "weather" */
  raining?: number; thundering?: number;
  /** "dimension": 0 overworld, -1 Nether, 1 End. */
  dimension?: number;
  /** "gametick": the world's time. */
  time?: number;
  /** "structure": which one, how it was turned (0-3, a quarter each) and its size [x, y, z]. */
  name?: string; rotation?: number; size?: [number, number, number];
  /** "gui": the menu's id, the button's id, what happened, the text boxes' values. */
  gui?: string; id?: string; action?: 'click' | 'submit' | 'input' | 'close' | 'slot' | 'message';
  values?: { [inputId: string]: string };
  /** "gui", action "message": what an html menu sent (mcre.send). */
  data?: any;
  /** "gui": what's in the menu's item slots now (see SlotsElement); action "slot": which slot changed. */
  slots?: { [slotsId: string]: (ItemStack | null)[] }; index?: number;
  /** "gui" / "message": the mod it's for. ("message" carries what was sent as e.data.) */
  mod?: string;
}

/** A stack of items. */
interface ItemStack { item: Name; count: number; data?: number; }

/** A world event's handler. Return a Promise if you like; errors are listed with the mod. */
type Handler = (e: GameEvent & { [k: string]: any }) => void | Promise<void>;

type WorldEventName =
  | 'start' | 'stop' | 'dimension' | 'join' | 'leave' | 'respawn'
  | 'use' | 'place' | 'break' | 'step' | 'tick' | 'useItem' | 'useItemOn'
  | 'eat' | 'craft' | 'smelt' | 'attack' | 'interact' | 'hurt' | 'death' | 'spawn'
  | 'chat' | 'explode' | 'weather' | 'gametick' | 'gui' | 'message' | 'structure'
  /** a "throwable" mod item landed: e.item, e.x/y/z, e.entity (what it hit, if anything), e.player */
  | 'hit'
  /** this mod's settings changed (e.values: all of them) */
  | 'settings';

interface CommandContext {
  player: Player;
  /** The words after the command's name. */
  args: string[];
  /** Everything typed, "/name ..." */
  text: string;
  /** Typed by the player whose world it is (single player: always). */
  isHost: boolean;
}

interface CommandOptions {
  /** "host": only the player whose world it is may use it. Default "everyone". */
  permission?: 'everyone' | 'host';
  /** Shown by /help. */
  description?: string;
  /** What follows the name, for /help: "<player> <amount>". */
  usage?: string;
}

interface ModApi {
  /** This mod's id (manifest.json). */
  readonly id: string;
  /** A world event - fires once, where the world is (single player or the host). */
  on(event: WorldEventName, fn: Handler): void;
  /** "/name ..." typed in chat. */
  command(name: string, fn: (c: CommandContext) => void | Promise<void>, options?: CommandOptions): void;
  /** Data to client.on("message") on that player's device ("all": everyone's). */
  send(player: Player | number | 'all', data: any): void;
  /** This device's values of the settings in manifest.json ("settings"). Where the world is,
   *  they're the host's; in client code, that player's own. Changes: on("settings"), e.values. */
  readonly settings: {
    get(id: string): any;
    all(): { [id: string]: any };
    /** Change one (kept, like a change in the Settings dialog; the value is fitted to the setting). */
    set(id: string, value: any): void;
  };
}

interface WorldApi {
  setBlock(x: number, y: number, z: number, block: Name, data?: number): void;
  setData(x: number, y: number, z: number, data: number): void;
  getBlock(x: number, y: number, z: number): Promise<{ block: Name; data: number }>;
  /** A "tick" event for a scripted block, this many game ticks (20 a second) from now. */
  scheduleTick(x: number, y: number, z: number, ticks: number): void;
  spawnItem(x: number, y: number, z: number, item: Name, count?: number): void;
  explode(x: number, y: number, z: number, power?: number, fire?: boolean): void;
  /** The world's time in ticks (a day is 19200; 0 is sunrise). */
  time(): Promise<number>;
  setTime(t: number): void;
  /** Is it raining / thundering? */
  weather(): Promise<{ raining: boolean; thundering: boolean }>;
  /** Clear skies, rain (snow where it's cold) or a thunderstorm - for this many seconds, or (none
   *  given) as long as the game's own weather would last. */
  setWeather(kind: 'clear' | 'rain' | 'thunder', seconds?: number): void;
  /** A sound everyone nearby hears, e.g. "random.pop". */
  sound(name: string, x: number, y: number, z: number, volume?: number, pitch?: number): void;
  /** What's in a container (chest, furnace, dispenser, hopper...), slot by slot; null if there's none. */
  container(x: number, y: number, z: number): Promise<(ItemStack | null)[] | null>;
  /** Put items in one slot of a container (item null: empty it). */
  setSlot(x: number, y: number, z: number, slot: number, item: Name | ItemStack | null, count?: number, data?: number): void;
  /** Fill a container from a loot table ("chests/hut" for your own loot_tables/chests/hut.json,
   *  "<mod>:<path>", or the game's: "minecraft:chests/simple_dungeon"...). */
  fillLoot(x: number, y: number, z: number, table: string): void;
  /** Drop a loot table's items there. */
  dropLoot(x: number, y: number, z: number, table: string): void;
  /** Roll a loot table without placing anything. */
  rollLoot(table: string): Promise<ItemStack[]>;
  /** Build one of the mods' worldgen structures with its lowest north-west corner here
   *  ("<name>" for your own worldgen/<name>.json); rotation 0-3 quarters (default: random if it turns). */
  placeStructure(name: string, x: number, y: number, z: number, rotation?: number): void;
  /** A creature: "<name>" (your mod's mobs/<name>.json, or the game's: "pig"), "<mod>:<name>"
   *  or "minecraft:pig". A Promise of its entity id (0 if it couldn't be made). */
  spawnEntity(type: string, x: number, y: number, z: number): Promise<number>;

  // --- creatures (a player, or any creature's id, works in all of these) ---
  /** Every creature, those of one type ("zombie", "minecraft:zombie", "<mod>:<name>"), or
   *  those near a point (radius 16 unless given). */
  entities(filter?: string | { type?: string; x?: number; y?: number; z?: number; radius?: number; limit?: number }): Promise<Creature[]>;
  /** One creature in detail; null if it's gone. */
  entity(id: number | Player | Creature): Promise<CreatureDetail | null>;
  /** Put it there (yaw / pitch in degrees, optional). */
  moveEntity(id: number | Player | Creature, x: number, y: number, z: number, yaw?: number, pitch?: number): void;
  /** Add to its motion (blocks per tick; 0.4 up is about a jump). */
  pushEntity(id: number | Player | Creature, dx: number, dy: number, dz: number): void;
  damageEntity(id: number | Player | Creature, amount: number, source?: number | Player | Creature): void;
  healEntity(id: number | Player | Creature, amount: number): void;
  /** Effects: speed, slowness, haste, mining_fatigue, strength, instant_health, instant_damage,
   *  jump_boost, nausea, regeneration, resistance, fire_resistance, water_breathing,
   *  invisibility, blindness, night_vision, hunger, weakness, poison, wither. */
  addEffect(id: number | Player | Creature, effect: string, seconds?: number, level?: number): void;
  /** One effect, or (none given) all of them. */
  removeEffect(id: number | Player | Creature, effect?: string): void;
  /** Seconds (default 8); 0 puts it out. */
  setOnFire(id: number | Player | Creature, seconds?: number): void;
  /** Who a creature goes for (null: nobody). */
  setTarget(id: number | Creature, target: number | Player | Creature | null): void;
  /** Walk there, if it can find a way (up to 32 blocks). */
  walkTo(id: number | Creature, x: number, y: number, z: number): void;
  /** Gone, without drops (never a player). */
  removeEntity(id: number | Creature): void;

  /** Particles everyone nearby sees: flame, smoke, large_smoke, heart, crit, enchanted_hit,
   *  portal, explosion, large_explosion, huge_explosion, lava, splash, bubble, dust, effect,
   *  entity_effect, enchant, angry_villager, happy_villager, snowball, slime, item, block. */
  particle(name: string, x: number, y: number, z: number, options?: {
    count?: number; spread?: number | [number, number, number]; speed?: number;
    /** dust / effect / entity_effect: "#ff8800", 0xff8800 or [r, g, b] */
    color?: string | number | [number, number, number];
    /** "item" / "block" particles: which */
    item?: Name; block?: Name;
  }): void;

  // --- signs, and data kept on a block ---
  /** A sign's 4 lines; null if there's no sign there. */
  signText(x: number, y: number, z: number): Promise<string[] | null>;
  /** Up to 4 lines of up to 15 letters (an array, or one string with \n). */
  setSignText(x: number, y: number, z: number, lines: string[] | string): void;
  /** What your mod kept on the block there (undefined: nothing, or the block changed). */
  getBlockData(x: number, y: number, z: number): Promise<any>;
  /** Keep a value (anything JSON) on the block there, saved with the world and dropped when
   *  the block is broken or replaced; null removes it. A Promise of whether it was kept
   *  (false: there's no block there). Where the world is only. */
  setBlockData(x: number, y: number, z: number, value: any): Promise<boolean>;
  /** Rules the game itself enforces from now on (scripts can't stop things in time; rules can).
   *  The same id replaces a set; null removes it. Gone when the scripts stop. */
  setRules(id: string, rules: Rules | null): void;
}

/** What the game refuses (a mod's rules/<name>.json has the same form). */
interface Rules {
  no_break?: Name | Name[]; no_place?: Name | Name[]; no_use?: Name | Name[];
  /** Creatures ("minecraft:player", "<mod>:<name>", "*") a kind of damage doesn't hurt. A plain
   *  string: that cause, for players. */
  no_damage?: string | Array<string | { entity?: string | string[]; cause?: DamageCause }>;
  /** false: players can't hurt players; explosions break nothing; fire doesn't spread. */
  pvp?: boolean; explosions_break_blocks?: boolean; fire_spreads?: boolean;
  explosion_proof?: Name | Name[];
  no_spawn?: string | string[];
  /** Only inside this box of blocks [x1, y1, z1, x2, y2, z2], and / or this dimension. */
  area?: [number, number, number, number, number, number];
  dimension?: 'overworld' | 'nether' | 'end' | 'any';
  /** Block rules apply to creative players too. */
  creative?: boolean;
  rules?: Rules[];
}
type DamageCause = 'any' | 'fall' | 'fire' | 'lava' | 'drown' | 'explosion' | 'attack' | 'projectile' | 'magic' | 'void' | 'suffocation' | 'other';

interface PlayersApi {
  all(): Promise<Player[]>;
  message(player: Player | number | 'all', text: string): void;
  /** item: a name ("minecraft:wool:14" for a variant) or a stack ({item, data}, e.g. from client.items()). */
  give(player: Player | number, item: Name | ItemStack, count?: number): void;
  /** Negative amounts hurt. */
  heal(player: Player | number, amount: number): void;
  /** y null: onto the ground there. Never into blocks or off the world. */
  teleport(player: Player | number, x: number, y: number | null, z: number): void;
  /** Everything a player carries: slots 0-8 the hotbar, 9-35 the rest; armour head, chest, legs, feet. */
  inventory(player: Player | number): Promise<{ slots: (ItemStack | null)[]; armor: (ItemStack | null)[]; selected: number } | null>;
  /** Put items in one of a player's slots (0-35, or "head" / "chest" / "legs" / "feet"); item null empties it. */
  setSlot(player: Player | number, slot: number | 'head' | 'chest' | 'legs' | 'feet', item: Name | ItemStack | null, count?: number, data?: number): void;
  /** Take up to count of an item from a player (data: only that variant); how many were taken. */
  take(player: Player | number, item: Name, count?: number, data?: number): Promise<number>;
  /** Empty a player's inventory (armorToo: the armour as well). */
  clear(player: Player | number, armorToo?: boolean): void;
}

interface TextElement { type: 'text'; text: string; color?: string; size?: number; align?: 'left' | 'center' | 'right'; bold?: boolean; }
interface ButtonElement {
  type: 'button'; id: string; text: string; color?: string; textColor?: string;
  /** An item ("minecraft:diamond") or a picture in the mod ("textures/gui/coin.png"). */
  icon?: string;
}
/** A picture in the mod, or an item's icon. */
interface ImageElement { type: 'image'; src?: string; item?: Name; width?: number; height?: number; align?: 'left' | 'center' | 'right'; }
/** Elements in columns: up to "columns", fewer when the screen is narrow. */
interface GridElement { type: 'grid'; columns?: number; elements: Element[]; }
/** live: true - a "gui" event with action "input" for every change (a search as you type). */
interface InputElement { type: 'input'; id: string; placeholder?: string; value?: string; live?: boolean; }
interface RowElement { type: 'row'; elements: Element[]; }
interface DividerElement { type: 'divider'; }
/** Item slots the player can move items in and out of. Every change is a "gui" event with
 *  action "slot"; every gui event carries e.slots (what's in each slots element). */
interface SlotsElement {
  type: 'slots'; id: string;
  /** How many slots (default: as many as items), and per row (up to 9). */
  count?: number; columns?: number;
  /** What's in them. Leave it out when updating an open menu to keep what's there. */
  items?: (ItemStack | Name | null)[];
  /** May the player put items in / take them out (default true). put: false = an output slot. */
  put?: boolean; take?: boolean;
  /** Only these items may go in. */
  accept?: Name[];
  /** true: the script looks after what's left when the menu closes. Otherwise it goes back to
   *  the player (from slots they can put into). */
  keep?: boolean;
}
/** The player's own inventory, to move items to and from. */
interface InventoryElement { type: 'inventory'; title?: string; }
type Element = TextElement | ButtonElement | InputElement | RowElement | DividerElement | SlotsElement | InventoryElement | ImageElement | GridElement;

/** How a drawn menu looks (all optional; it still adapts to phones and computers). */
interface MenuStyle {
  /** "#203040", or a picture in the mod ("textures/gui/bg.png"). */
  background?: string;
  backgroundSize?: 'cover' | 'tile';
  border?: string; color?: string; title?: string; accent?: string;
  /** Rounded corners, 0-24. */
  radius?: number;
  font?: 'pixel' | 'sans' | 'serif';
}

interface Menu {
  /** Open a menu again with the same id to update it. */
  id: string;
  /** false: a panel - beside the game instead of over it. No dimmed backdrop, the game keeps the
   *  mouse and keys everywhere else, several can be open at once (one per id). Place it with
   *  position and width / height in CSS pixels - client.on("screen") says where the game's
   *  inventory window is, to dock one beside it. No Close button unless closeButton: true. */
  modal?: boolean;
  /** A panel's place: {left | right, top | bottom} in CSS pixels. */
  position?: { left?: number; right?: number; top?: number; bottom?: number };
  /** A panel kept but out of sight (an html one keeps running); open it again without to show it. */
  hidden?: boolean;
  title?: string;
  /** In pixels, 200-720 (default 380). For an html menu: pixels or "80%". */
  width?: number | string;
  height?: number | string;
  elements?: Element[];
  style?: MenuStyle;
  /** Your own page instead of elements: "gui/shop.html" in the mod. It gets window.mcre and nothing
   *  else - no internet, no game page: data, send(x), on(fn), close(), touch, and
   *    icons(items) -> Promise [{item, data, id, name, max, icon}] (icon: a 32 x 32 picture URL),
   *    asset(path) -> Promise URL of one of the game's pictures ("font/default8.png"),
   *    panel (true for a panel), area(rects | null): only these parts [{x, y, width, height}] of a
   *    panel show and take the mouse - the game gets the rest. A panel hands the game the keys it
   *    doesn't type with (or preventDefault) and the mouse's movement. */
  html?: string;
  /** For an html menu: mcre.data; opening it again with the same id passes new data to mcre.on. */
  data?: any;
  /** false: no Close button (Esc still closes it). */
  closeButton?: boolean;
}

interface GuiApi {
  open(player: Player | number, menu: Menu): void;
  close(player: Player | number): void;
}

interface StorageApi {
  /** Kept with the world, where the world is (a joined device's storage is empty). */
  get(key: string): any;
  set(key: string, value: any): void;
  all(): { [key: string]: any };
}

type ClientEventName = 'start' | 'stop' | 'tick' | 'key' | 'message' | 'gui' | 'dimension' | 'settings'
  /** the game's open screen changed (see ScreenInfo) - also when it moves, or the held stack changes */
  | 'screen'
  /** one of this mod's "key" settings went down / up: e.id, e.down, e.code (Options > Controls lists them) */
  | 'keybind'
  /** a click on a slot of the game's inventory screens: e.area, e.index, e.item, e.button, e.shift */
  | 'slotClick';

/** The game's own screen on this device (client.screen(), client.on("screen")). */
interface ScreenInfo {
  /** "none" (playing), "inventory", "crafting", "chest", "furnace", "container" (dispenser, dropper,
   *  hopper), "creative", "station" (enchanting / anvil / brewing), "trading", "pause", "chat",
   *  "death", "sign", "bed", "menu" (no world), "other". */
  screen: string;
  /** Where an inventory screen draws its window, in CSS pixels; null for other screens. */
  rect: { x: number; y: number; width: number; height: number } | null;
  /** The stack on the cursor of an inventory screen. */
  held: ItemStack | null;
  /** The window's size in CSS pixels, and CSS pixels per GUI pixel (a slot is 18 GUI pixels). */
  width: number; height: number; scale: number;
  /** The screen's close X, in CSS pixels (null: it has none). It is always on top: the game cuts
   *  it out of every mod panel, so lay a panel out round it rather than under it. */
  close?: { x: number; y: number; width: number; height: number } | null;
}

interface KeyEvent extends GameEvent { key: string; code: string; down: boolean; }

interface ClientApi {
  /** This device's own events: "key" {key, code, down}, "tick" {player}, "message" {data}... */
  on(event: ClientEventName, fn: Handler): void;
  /** True where the world is (single player or the host). */
  readonly isHost: boolean;
  /** This device's player. */
  player(): Promise<Player>;
  /** To mod.on("message") where the world is. */
  send(data: any): void;
  /** close(id): that menu or panel; close(): the menu and this mod's panels. */
  gui: { open(menu: Menu): void; close(id?: string): void; };
  /** A sound only this device hears. */
  sound(name: string, volume?: number, pitch?: number): void;
  /** A line in this device's chat. */
  message(text: string): void;
  /** A line of text at the top right; null removes it. */
  hud(id: string, text: string | null): void;
  /** What's open in the game on this device, and where. */
  screen(): Promise<ScreenInfo>;
  /** The game's Controls screen (Options > Controls > Key Bindings), on this mod's keys. */
  openControls(): void;
  /** The open inventory screen's slots by area, and changing one. */
  screenSlots(): Promise<{ [area: string]: (ItemStack | null)[] } | null>;
  setScreenSlot(area: string, index: number, item: Name | ItemStack | null, count?: number, data?: number): Promise<boolean>;
  /** true: clicks on the game's inventory slots are this mod's ("slotClick" decides). */
  captureSlots(on: boolean): void;
  /** What the game knows about an item. */
  itemInfo(item: Name | ItemStack): Promise<{ name: string; max: number; block: boolean; category: string; rarity: string; durability?: number; food?: number; armor?: string; id: number | null } | null>;
  /** The stack on the cursor of an open inventory screen (null: nothing). */
  held(): Promise<ItemStack | null>;
  /** Put a stack on that cursor (null: take it away). False when no inventory screen is open. */
  setHeld(item: Name | ItemStack | null, count?: number, data?: number): Promise<boolean>;
  /** Every block and item the game has - variants and mods' included - in the creative
   *  inventory's order, each a full stack. */
  items(): Promise<ItemStack[]>;
  /** Kept on this device for this mod, in every world (settings a player chose, their favourites...). */
  storage: { get(key: string): any; set(key: string, value: any): void; all(): { [key: string]: any } };
}
