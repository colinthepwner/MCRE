Introduction

Rube is Minecraft RE's mod loader: everything in the Mods tab goes through it. It loads
  - Rube mods: a .zip (or a folder) like this one - textures, sounds, blocks, items, recipes,
    creatures, structures, world generation and scripts (most of this page);
  - Java Edition mods: ModLoader and Forge mods for Minecraft 1.4.7, 1.5, 1.6 and 1.7.10, and Babric /
    Better Than Adventure mods for Beta 1.7.3 - the .jar as it is (see Java mods below);
  - Pocket Edition ModPE scripts (BlockLauncher's .js and .modpkg) and Java resource packs.
Mods of every kind run together, in one list.

This mod, the Example Pack, is a Rube mod. Turn it on in the Mods tab to see what a mod can do:
  - it changes how the game looks, sounds and reads: dirt turns purple, the apple turns gold,
    menu buttons pop instead of click, and both get new names;
  - it adds blocks, items and recipes: Example Ore underground (and in the Nether), which
    drops Example Gems (2 dirt make 2 as well), the glowing Example
    Block, the Example Counter (gem + planks), the slippery, falling Example Slide (gem +
    sand) and the Example Wand (gem + stick);
  - and scripts/main.js makes them do things: the Counter opens a menu, the Wand tells you
    what a block is, /example is a command, and K shows your coordinates.

Presets

Small mods to start from, one thing each - using the game's own textures, so they're all JSON and script. Download one, unzip it, change the "id" in manifest.json, then open the folder in the Mods tab (Add mod > Open a folder) and press Reload as you change it. They're kept up to date with the game.

In the game: Add mod > Browse mods > Sources, add https://colinthepwner.github.io/MCRE/modding/presets/index.json to install them from there.

What's inside

manifest.json         Who the mod is. Required:
                        "id": "example"        (lower-case letters, digits, . _ - ; must be unique)
                        "devices": "any"       what it's made for: "any", "computer" or "mobile".
                                               A label, not a lock - players see it in the Mods
                                               tab (and get a heads-up if they're on the other
                                               kind), and mod lists can show it too ("devices")
                      Shown in the Mods tab: "name", "version", "author", "description".
                      A mod isn't made for one version of the game: it keeps working as the
                      game updates. ("format" and "type" are fine to leave in; they're ignored.)
                      "platforms": {"computer": ["scripts/", "gui/"], "mobile": ["modpe/"]}
                        parts for one kind of device only: folders (or files) listed under
                        "computer" aren't loaded on phones and tablets, "mobile" ones not on
                        computers - one mod with a version for each (everything else loads
                        everywhere). Use "devices": "any" for such a mod.
                      "dependencies": ["other_mod", {"id": "nice_to_have", "optional": true}]
                        other mods this one needs: they're turned on with it and loaded first.
                        One that's missing shows in the Mods tab.
                      "settings": what players can change in the Mods tab (Settings) or with
                        /modsettings <id> in a world - each player's own:
                        {"id": "sparkle", "name": "Sparkles", "type": "toggle", "default": true}
                        {"id": "count", "type": "slider", "min": 0, "max": 20, "step": 1, "default": 6}
                        {"id": "count", "type": "number", "min": 0, "max": 1000, "default": 6}
                        {"id": "mode", "type": "choice", "options": ["easy", "hard"], "default": "easy"}
                        {"id": "motd", "type": "text", "default": "Hello"}
                        {"id": "menu_key", "name": "Open the menu", "type": "key", "default": "O"}
                          - a key the player picks. It's listed in Options > Controls > Key
                          Bindings under your mod's name, with the game's own keys (as in
                          Java), and in your Settings; it's a key code - "KeyO", "Digit1", "F8",
                          "Space". Scripts hear it: client.on("keybind", e => e.id === "menu_key"
                          && e.down ...) - whatever the player bound it to
                        ("description" on any: a line under it). Scripts read them with
                        mod.settings.get("sparkle") and hear changes: mod.on("settings").
pack.png              The icon in the Mods tab (64x64 looks good).

textures/blocks/<name>.png    Replaces one block texture.
textures/items/<name>.png     Replaces one item texture.
                      The names are in texture_names.txt (they're Minecraft Java Edition's
                      names, so textures from Java packs drop straight in). Any texture can also
                      be named by its number: textures/blocks/cell_<number>.png.
                      16x16 pixels; bigger pictures are shrunk to fit. For animated strips
                      only the first frame is used.

images/<path>.png     Replaces one of the game's picture files whole, same path as the game's
                      (e.g. images/mob/zombie.png, images/gui/gui.png, images/terrain.png).

sounds/<group>/<name><number>.ogg
                      Replaces the sound "<group>.<name>" - every variant of it. This pack's
                      sounds/random/click.ogg replaces "random.click" (menu buttons).
                      Several files (click1.ogg, click2.ogg...) play at random.

lang/en_US.lang       Lines of key=value that replace the game's text, e.g.
                      tile.dirt.name=Example Dirt

blocks/<name>.json    A new block, called "<mod id>:<name>" (this one: example:example_block).
                      Everything is optional; these are shortcuts, and scripts do the rest.
                        "name"        what it's called in the game
                        "texture"     a texture name: one of this mod's textures/blocks/<n>.png,
                                      or any of the game's (texture_names.txt). Different faces:
                                      {"top": "a", "bottom": "b", "side": "c"} (also "all",
                                      "up", "down", "north", "south", "east", "west")
                        "hardness"    how long it takes to break (stone is 1.5, dirt 0.5;
                                      -1 can't be broken)
                        "tool"        "pickaxe", "axe", "shovel" or "none"
                        "sound"       stone, wood, gravel, grass, metal, glass, cloth or sand
                        "light"       how much light it gives, 0-15 (a torch is 14)
                        "transparent" true for blocks you can see through (glass-like)
                        "drops"       "self" (default), "none", or an item; "drop_count"
                        "shape"       "cube" (default), "slab", "top_slab", "carpet", "layer",
                                      "plate", "path", "cactus", "post", "pillar", "table",
                                      "button", "cross" (drawn like a flower), "crop" (in rows like
                                      wheat, on farmland), "stairs" (like the game's stairs: data
                                      0-3 which way, +4 upside down), or your own box in
                                      pixels: [x1, y1, z1, x2, y2, z2], each 0-16
                                      (a slab is [0, 0, 0, 16, 8, 16]).
                                      A "slab" goes in as the top or bottom half by where it's
                                      clicked; "double": the block two of them make (one slab on
                                      another turns into it)
                        "collision"   false: players and mobs walk through it
                        "portal_to"   a dimension (dimensions/<name>.json): standing in it
                                      takes you there - use with "collision": false
                        "gravity"     true: falls like sand
                        "friction"    0.6 normal, 0.98 like ice ("slippery": true is ice)
                        "flammable"   true: catches fire and burns like wood
                        "container"   "furnace", "chest", "anvil" or "enchanting": it works as the game's
                                      furnace / chest / anvil / enchanting table. A furnace's "lit": the
                                      block it turns into while it burns. An enchanting one's
                                      "enchant_power": a factor on the levels it offers (1 the game's
                                      table, 0.5 half).
                        (furnace / chest:)
                                      (its screen; what's in it falls out when it's broken). A
                                      chest is drawn as the game's chest model with
                                      "chest_texture" (a Java chest picture in the mod); a
                                      furnace's heat: overrides/blocks "furnace_heat"
                        "crafting_table"  true or a level (1-...): it's a workbench - using it opens
                                      the crafting grid, and recipes with "station" up to its
                                      level can be made there (overrides/blocks: "station")
                        "fuel"        burns in a furnace for that many ticks (20 a second:
                                      coal 1600, a plank 300, a stick 100); true is a plank's
                        "scripted"    true: using it does nothing else - your script's "use"
                                      event decides (and it never places a block against it);
                                      its world.scheduleTick ticks reach the script too
                        "neighbor_updates"  true: your script hears mod.on("neighbor") when
                                      a block next to it changes
                        "entity_inside"  true: mod.on("inside") every tick something is in it
                                      (mud, quicksand, a bouncy cloud: change its motion)
                        "collision_box"  [x0, y0, z0, x1, y1, z1] in pixels - what it stops,
                                      when not its whole shape (mud you sink into: [0,0,0,16,10,16])
                        "leaves"      true: drawn like the game's leaves by Options > Graphics >
                                      Leaves - see-through on Fancy / Fanciest, solid on Fast
                                      with "texture_fast" (an opaque picture, same forms as
                                      "texture"; without it the same picture). Use with
                                      "transparent": true on a whole-cube block
                        "crop"        it grows on farmland like wheat: {"seed": item (planted on
                                      farmland with it), "stages": [blocks of this mod, the first
                                      just planted, the last ripe], "light": 9 (the light it needs),
                                      "speed": 1, "yield": [{"item": ..., "count": 3, "chance":
                                      0.25}, {"item": ..., "count": 2}] (what the ripe one drops),
                                      "blight": {...} (see Changing what's already there)}
                        "spark"       true: turns into fire after a moment if something that burns
                                      (or netherrack - a Nether portal frame) is next to it, else
                                      it goes out (place it with an item's "places")
                        "ignites"     true: sets fire around it now and then, as lava does
                        "burns_touching"  true: whatever touches it catches fire
                        "steams_water"  true: water flowing or poured onto it boils away
                        "creative"    false: left out of the creative inventory
                        "liquid"      a real liquid instead of a block (like water / lava: it
                                      flows, you swim or burn in it, buckets take it) - true for
                                      water's ways, or an object, every field optional:
                          "like"        "water" (default) or "lava": how it flows - lava spreads
                                        slowly and unevenly and fizzes away what it washes off
                          "acts"        "water", "lava" or "none": what it is to whoever is in it -
                                        swim / drown / get pushed, or burn and wade (default: like)
                          "still", "flowing"  its pictures (textures/blocks/<n>.png or the game's;
                                        default its "texture"). A vertical strip of square frames
                                        is animated - with Java's <n>.png.mcmeta ("frametime",
                                        "interpolate", "frames") next to it, or every frame a tick
                          "spread"      blocks it runs on flat ground, 1-7 (water 7, lava 3)
                          "spread_nether"  ... in the Nether (lava there: 7)
                          "tick_rate"   game ticks a flow step takes (water 5, lava 30)
                          "infinite"    two sources make a third between them (water's; default
                                        true for "like": "water")
                          "translucent" see-through like water (default) or solid like lava
                          "light"       light it gives, 0-15; "opacity" light it stops, 0-255
                          "color"       "#rrggbb" its pictures are tinted with
                          "fog_color"   "#rrggbb" - the view from inside it ("auto": its still
                                        picture's colour, darkened); "fog_density" (water 0.1)
                          "effects"     [{"effect": "poison", "seconds": 5, "level": 1,
                                        "chance": 1}] - on whoever is in it, every tick they are
                          "damage"      hurt each second in it (half hearts)
                          "sets_fire"   true: flammable blocks around it catch fire, as lava's
                          "mix"         [{"with": "water", "source": "minecraft:obsidian",
                                        "flowing": "minecraft:cobblestone"}] - next to "with"
                                        ("water" / "lava": anything acting as them, or a block /
                                        liquid name) its source / flowing blocks turn into those;
                                        mod.on("liquidmix") hears it
                          "bucket"      its filled bucket (an item): the game's empty bucket picks
                                        up a source as that item, and using the item pours one -
                                        "bucket_empty" what it leaves (default the bucket)
                          "aliases"     other block names that mean this liquid
                        A liquid takes a block id of its own (its data value is its level: 0
                        source, 1.. flowing, 8+ falling - world.setBlock(x, y, z, "<it>", 0)
                        places a source). Game rules: modLiquidFlow, modLiquidFire.

                       "result": item, "count": 1}
                      {"type": "shapeless", "ingredients": [item, item], "result": item}
                      {"type": "smelting", "input": item, "result": item}
                      {"type": "fuel", "item": item, "burn_time": 400} - any item a furnace
                      fuel, the game's too (0: not a fuel any more)
                      Any crafting recipe may add "station": n - the workbench level it needs (0:
                      the inventory's own grid, 1: the game's crafting table, more: blocks with
                      "crafting_table": n) - and "time": ticks it takes (the arrow fills as it
                      crafts; game rules craftSpeedPerLevel / craftSpeedPerStation speed it up)
                      - and "skills": the skills a player needs to make it ("masonry",

                      recipes that make it, the game's or another mod's ("kind": crafting,
                      smelting or all; "input": item for what a furnace smelts). Add your own
                      recipe for the same item to replace one.
                      An item is "<name>" (this mod's), "<mod id>:<name>" (another mod's) or
                      "minecraft:<name>" (the game's, Java names like minecraft:iron_ingot;
                      add ":<number>" for a variant, e.g. minecraft:wool:14).
Textures for new things are 16x16; the game makes room for as many as your device can hold.

Block models

models/block/<name>.json  A Java block model - exactly what Blockbench exports ("Java Block/Item"):
                       {"textures": {"side": "block/stone", "gem": "example:block/example_block"},
                        "elements": [{"from": [0, 0, 0], "to": [16, 8, 16],
                          "rotation": {"origin": [8, 8, 8], "axis": "y", "angle": 22.5},
                          "faces": {"north": {"uv": [0, 8, 16, 16], "texture": "#side",
                                              "cullface": "north", "rotation": 90}, ...}}]}
                       Any number of boxes, turned -45 to 45 degrees, each face its own texture,
                       uv and rotation; "parent" works with your own models or the usual ones
                       (block/cube_all, cube_column, cube_bottom_top, orientable, cross, slab...).
                       Textures: "<mod id>:block/<name>" is your textures/blocks/<name>.png;
                       "block/<name>" or "minecraft:block/<name>" the game's (newer names like
                       oak_planks work too).
                       Use it from a block: "model": "block/<name>" - or name the model like the
                       block and leave it out. "rotate": "horizontal" turns the block to face
                       whoever places it (a Java blockstates/<name>.json with facing=... variants
                       does the same). Light passes through a block with a model; it can be
                       walked on where the model is (or give "shape" a box for its collision).
                       Walls, fences, panes: give a box "connect": {"north": true} (or south,
                       east, west; "up": the post where the run isn't straight; false - only when
                       NOT joined) and it's drawn only when the block joins up that way - with
                       another such block, a fence or a solid block beside it.
                       See example_pedestal and example_chair. A Java mod's assets/<id>/models,
                       textures and blockstates folders work as they are.

Scripts

scripts/<anything>.js  JavaScript that makes your mod do things. scripts/main.js in this mod is
                       a full example; read it alongside this.

Write your script once. It runs on every device in the game - yours, and everyone who joins you -
and the game sorts out where each thing happens:
  - World events (mod.on) fire once, where the world is, never once per player.
  - world.* and players.* work from anywhere; the game sends them where they need to go.
  - Anything aimed at a player (a menu, items, teleporting, healing, a message) reaches that
    player, whichever device they're on.
  - client.* is "this device": its screen, its keys, its sounds, its own player.
In single player it's all one device, and the same script just works.

Names: a block or item is "<mod id>:<name>", "minecraft:<java name>" (e.g. minecraft:stone),
"air", or just "<name>" for your own mod's. A player is {id, name, x, y, z, health}; pass it
(or its id) wherever a player goes.

Game modes

A mod can add a game mode to the Create World screen - manifest.json:
  "game_mode": {"name": "My Mode", "description": "one line under the button",
                "hardcore": true, "hunger": true, "default": true}
Its gameplay - changes to existing things, recipes (and removed ones), fuels, world generation,
creature spawning, rules, biomes, world types and its scripts - is then only on in worlds made
in that mode; its blocks, items and creatures always exist. So players keep the mod installed
and still play ordinary worlds. "hardcore": one life, Hard difficulty, the world is deleted on
death. "hunger": hunger stays on whatever Options says. "default": the screen starts on it.
"world_sizes": ["extreme", "infinite"] - the only world sizes it can be played in (tiny, small,
normal, large, extreme, infinite; left out: any).
"world_height": 256 - its worlds are always that tall (128 or 256; left out: the Tall World button).
"world_type": "<type>" - its worlds always use that world type (worldtypes/<type>.json); "difficulty":
"hard" (or 0-3), "difficulty_locked": true (held there), "difficulty_name": what that level is called.
A world type's "mode_only": true (or a mode's id) - offered only with that game mode.

Any item, block or creature - the game's own or another mod's - can be changed with the same keys
new ones use. One thing per file (the file's name is the game's name), or "target":
"minecraft:iron_pickaxe", or several: {"minecraft:stone": {...}, "minecraft:dirt": {...}}.

Rules

Scripts hear about things after they happen, so they can't stop them. Rules can: the game checks
them at the moment something happens.
rules/<name>.json     {"no_break": [blocks], "no_place": [blocks], "no_use": [blocks],
                       "no_damage": [{"entity": "minecraft:player", "cause": "fall"}],
                       "pvp": false, "explosions_break_blocks": false,
                       "explosion_proof": [blocks], "fire_spreads": false,
                       "no_spawn": ["minecraft:creeper"]}
                      What players can do: "no_eat": [items], "no_wear": [items] (or "*": any
                      armour - it comes off), "no_sprint": true, "no_sleep": true; "players":
                      [names] limits a set to those players (a script's curse on one player).
                      "craft_levels": n - their crafting quality is judged as if their level were
                      n higher (negative: lower - a clumsiness curse, -20); "always_eat": [items]
                      - they may eat these whenever eating is allowed at all, a full bar or not
                      (a craving). A script's sets reach joined players' games too.
                      Blocks can be "*" (any). Creatures: "minecraft:player", "minecraft:pig",
                      "<mod id>:<name>", or "*". Causes: any, fall, fire, lava, drown, explosion,
                      attack, projectile, magic, void, suffocation, other. "no_damage": ["fall"]
                      (just causes) means players.
                      Add "area": [x1, y1, z1, x2, y2, z2] (a box of blocks) and / or
                      "dimension" to limit them; {"rules": [{...}, {...}]} for several areas.
                      Block rules leave players in creative mode alone - "creative": true
                      includes them.
In a block: "explosion_proof": true. In a creature: "immune": ["fall", "fire"].
From a script: world.setRules(id, {...}) turns a set of rules on (the same form; the same id
replaces it, null turns it off) - e.g. protect an arena while a game runs. See /example protect.

loot_tables/<path>.json  A loot table called "<mod id>:<path>" (this mod's chests/shrine.json is
                       example:chests/shrine). Java's format works as it is:
                         {"pools": [{"rolls": {"min": 2, "max": 4}, "entries": [
                           {"type": "minecraft:item", "name": "minecraft:diamond", "weight": 2,
                            "functions": [{"function": "minecraft:set_count",
                                           "count": {"min": 1, "max": 3}}]},

                           {"type": "minecraft:loot_table", "name": "another_table"}]}]}
                       (set_count and set_data are used; other functions are ignored.) Or short:
                         {"rolls": [1, 3], "items": [{"item": "minecraft:apple",
                          "count": [1, 4], "weight": 3}], "empty": 2}

                       An entry's "min_day" / "min_y" / "max_y": only in chests from that day of the
                       world on / at those heights. "artifacts": {"chance": 0.25, "min_day": 40,
                       "achievement": "<id>", "items": [...]} - one of these, once a world each, may
                       take a stack's place in a chest of this table (one per structure).

                       desert_pyramid, jungle_temple, jungle_temple_dispenser, stronghold_corridor,
                       stronghold_crossing, stronghold_library or village_blacksmith fills those

Use them in blocks ("loot": "my_table" drops from the table instead of "drops"), in structures
(above) and from scripts (world.fillLoot, dropLoot, rollLoot).

Order

Mods higher in the list win when two change the same thing. A mod you add goes on top.

The Mods tab

Add mod takes a .zip, a .jar, a .js / .modpkg, a resource pack, a structure file or a folder
(drop a file on the game to add it too). Each mod's row shows:
  - whether it's on (On / Off) - its place in the list decides which mod wins (see Order);
  - how well it runs: Works, Partly works (with what isn't here yet - "custom-drawn blocks
    and items", "new potion effects"...) or Can't run (and why: made for a version Rube doesn't
    load, a server plugin, source code instead of the mod...);
  - what it's made for: any device, computers or phones;
  - its problems, counted (open the mod to read them) and its Settings, if it has any.
Download gives the mod back as a file, Remove deletes it, Reload loads every mod again (or
/reload in a world).

Worlds and mods

A world remembers the exact mods it was saved with. In the world list, a world saved with
other mods is greyed out ("Other mods" or "Mods missing"); open it to see which mods it wants
turned on or off, and Switch mods sets them for you. Worlds from before this existed open with
any mods.

Playing together

Only the host's mods run in a shared game. Joining a game with mods asks first and lists them;
Join downloads the ones you don't have ("Keep these mods after I leave" adds them to your
list, switched off). While
you're there your own mods are off; leaving brings them back. Blocks, items, creatures and
world generation come from the host's mods for everyone; scripts and Java mods' code run on
the host, and what they show (menus, messages, sounds) reaches the players they're for.

When mods overlap

Mods often add the same thing - copper from three mods, three kinds of rubies. Rube makes them
count as one where it matters: a recipe that asks for one mod's copper takes any mod's
copper (Forge's ore dictionary names), so mixed mods still craft. When
two mods change the same texture, sound or setting, the higher one in the list wins.

Making a mod

Start from this one: Download it from the Mods tab, unzip it, change it.
  - Open the folder, not a .zip, while you work: Add mod -> Open a folder (Chrome and Edge).
    The game reads it straight from your disk. Change a file, then press Reload in the Mods
    tab - or type /reload in a world to reload without leaving it (new blocks, textures,
    recipes and scripts all come in; scripts start again; players who joined you keep the
    old version until they join again). Download on a folder's row makes the .zip to share. (Other browsers: Add mod the .zip again - the same id, name and author
    replace the old copy.)
  - Problems: anything in a mod the game can't use - a recipe with an unknown item, a texture
    that isn't there, broken JSON, a script error with its file and line - is listed in the
    mod's panel in the Mods tab, and counted on its row.
  - Autocomplete: types/mcre.d.ts describes the scripting API and jsconfig.json points your
    editor at it. Open the mod's folder in VS Code (or any editor that reads TypeScript
    types) and mod., world., players. ... complete as you type, with their notes.

Sharing a mod

Add mod -> Browse mods lists mods from mod lists and installs them (with what they need).
A mod list is one JSON file anyone can put online (GitHub Pages works):
  {"name": "My mods", "mods": [{"id": "example", "name": "Example Pack", "author": "you",
    "version": "1.0", "devices": "any", "description": "...", "url": "example.zip", "icon": "example.png",
    "tags": ["blocks"], "dependencies": [], "sha256": "(optional: the .zip's SHA-256)"}]}
"url" and "icon" can be relative to the list. Players add a list under Sources by its

Old Pocket Edition mods (ModPE)

BlockLauncher's ModPE scripts work: Add mod -> choose the .js (or a .modpkg). Their blocks, items,
food, armour, recipes and hooks (useItem, destroyBlock, modTick, procCmd, attackHook, deathHook,
chatHook...) run as they did on a phone, with Pocket Edition's ids and texture names. Their
menus (Android buttons, panels, text boxes, checkboxes, sliders, dialogs, toasts) are drawn
by the game, for touch and mouse alike - with a mouse, M frees the cursor for a mod's buttons
while playing. ModPE scripts run where the world is (single player, or the host).
Rhino's own JavaScript works too (new X() { ... } listeners, for each (... in ...)). The phone's
storage is there as /sdcard: what a script writes stays on this device, and files a mod ships
under sdcard/ in its zip are there to read (a config it expects). The network isn't: a script
sees what a phone with no connection saw (most just skip their update check).

Java resource packs

A Java Edition resource pack .zip (with pack.mcmeta) can be added as it is: its block and item
textures, sounds and en_us.lang lines are used.

Java mods

Add mod -> choose the .jar (or the .zip it came as). Rube runs the mod's own Java code - no
Java install, nothing to set up - and turns what it registers into the game's own things:
  - blocks, items, tools, armour, food, recipes, smelting and fuel;
  - creatures with their models, textures, drops and spawning, and how their models move;
  - biomes, world types, ore and structure generation, and new dimensions with their portals;
  - its key bindings and config options, as Settings in the Mods tab;
  - what its code does in the world: using items and blocks, ticking blocks and creatures,
    commands, chat, events.
Loaders: ModLoader and Forge (Minecraft 1.4.7, 1.5.x, 1.6.4 and 1.7.10), Babric with StationAPI and
Better Than Adventure (Beta 1.7.3). Mods for different Minecraft versions can be on together.
A mod that needs a library (LomLib, Player API...) gets it downloaded for it when you're
online; one it can't find is named on the mod's row.
What Rube can't do for a Java mod is said on its row (see The Mods tab): parts drawn by the
mod's own OpenGL code it can't reproduce, and changes it makes to Minecraft's own classes,
leave just that part out - the rest of the mod still works.

Types (mcre.d.ts)

Every script's API, for editors that read TypeScript types (VS Code...): put it next to your scripts with a jsconfig.json and mod., world.... complete as you type. Download mcre.d.ts

// Minecraft RE - mod scripting API, for editors (VS Code and others read this file and complete
// the API as you type). Keep it next to your scripts: this mod's jsconfig.json points the editor
// at types/*.d.ts and scripts/*.js. Nothing here runs - it only describes what the game gives
// every script: mod, world, players, gui, storage, client and log.

/** A block or item: "<mod id>:<name>", "minecraft:<java name>" (e.g. "minecraft:stone"),
 *  "air", or just "<name>" for your own mod's. Add ":<data>" for a variant ("minecraft:wool:14").
 *  Java 1.7's blocks go by their 1.7 names ("minecraft:stained_glass:14", "minecraft:log2:1",
 *  "minecraft:double_plant:0", "minecraft:red_flower:9" - see the README's Names). */
type Name = string;

/** A player. Pass it (or its id) wherever a player goes. */
interface Player {
  id: number;
  name: string;
  /** Feet position. */
  x: number; y: number; z: number;
  health: number;
}

/** A creature (or other entity) in an event. */
interface Creature {
  id: number;
  /** "minecraft:zombie", "<mod id>:<name>" for a mod's own creature, ... */
  type: string;
  x: number; y: number; z: number;
  health?: number;
  /** Set when the creature is a player. */
  name?: string;
}

/** world.entity(): a creature in detail. */
interface CreatureDetail extends Creature {
  yaw: number; pitch: number;
  motion: [number, number, number];
  onGround: boolean;
  /** Ticks of fire left. */
  fire: number;
  maxHealth?: number;
  /** The creature it's going for (0: none). */
  target?: number;
  effects?: { effect: string; seconds: number; level: number }[];
  /** A mod creature's model parts hidden on it now (world.setPartVisible). */
  hiddenParts?: string[];
  /** A mod creature's picture: 0 its "texture", n its n-th "textures" one (world.setMobTexture). */
  texture?: number;
}

/** Everything an event can carry. Which fields are set depends on the event (see mod.on). */
interface GameEvent {
  /** The event's name. */
  t: string;
  /** A block: its name, data value and position. */
  block?: Name; data?: number; x?: number; y?: number; z?: number;
  /** An item: its name and how many. */
  item?: Name; count?: number;
  /** The face of a block an item was used on, or ("place") the face clicked to place it
   *  (0 down, 1 up, 2 north, 3 south, 4 west, 5 east). */
  face?: number;
  /** Whoever did it. */
  player?: Player;
  /** The creature it happened to, and (hurt / death) what did it. */
  entity?: Creature; source?: Creature | null;
  damage?: number;
  /** "chat" */
  text?: string;
  /** "explode" */
  power?: number;
  /** "weather" */
  raining?: number; thundering?: number;
  /** "dispense": the slot it came from, which way the dispenser faces (as face), and whether a
   *  Java mod dispensed it its own way (1) rather than the game (0). */
  slot?: number; facing?: number; handled?: number;
  /** "enchant" */
  enchantment?: string; level?: number;
  /** "jukebox": the disc's music (its item's "record"); e.action is "insert" or "eject". */
  sound?: string;
  /** "dimension": 0 overworld, -1 Nether, 1 End. */
  dimension?: number;
  /** "sky": a script set the sky's colour (world.setSkyColor) - null: given back. */
  sky?: { color: string | null; mod: string };
  /** "afk": gone AFK (true) or back (false), and what they play on. */
  afk?: boolean; device?: Device;
  /** "bot": what the world's bot did - spawn / despawn / done / fail / died / rename; its name,
   *  the job (done / fail), its owner (spawn), its old name (rename). */
  action?: 'spawn' | 'despawn' | 'done' | 'fail' | 'died' | 'rename'; bot?: string; task?: string; owner?: string; was?: string;
  /** "edge": Edge Assist started holding the player at a drop ("hold"), they pushed on and went
   *  over ("through"), or they stopped / walked away ("free"). "tutorial": the walkthrough's section
   *  ("gameplay", "inventory", "crafting", "crafting_table", "furnace", "minecart", "boat", "fishing",
   *  "bed", "container", "dispenser", "redstone_and_piston", "portal"). */
  state?: 'hold' | 'through' | 'free' | string;
  /** "tutorial": what happened - it started, moved on a step, went into a section, or its main part
   *  ended (time runs again, monsters come, the spawn area opens); the main track's current text id
   *  ("IDS_TUTORIAL_TASK_CHOP_WOOD"...); whether the main part is over. */
  what?: 'start' | 'step' | 'state' | 'complete'; step?: string; complete?: boolean;
  /** "gametick": the world's time. */
  time?: number;
  /** "structure": which one, how it was turned (0-3, a quarter each) and its size [x, y, z]. */
  name?: string; rotation?: number; size?: [number, number, number];
  /** "gui": the menu's id, the button's id, what happened, the text boxes' values. */
  gui?: string; id?: string; action?: 'click' | 'submit' | 'input' | 'close' | 'slot' | 'message';
  values?: { [inputId: string]: string };
  /** "gui", action "message": what an html menu sent (mcre.send). */
  data?: any;
  /** "gui": what's in the menu's item slots now (see SlotsElement); action "slot": which slot changed. */
  slots?: { [slotsId: string]: (ItemStack | null)[] }; index?: number;
  /** "gui" / "message": the mod it's for. ("message" carries what was sent as e.data.) */
  mod?: string;
}

/** A stack of items. */

/** A monster spawner (world.spawner): what it makes and how often. Times are in ticks (20 a second). */
interface SpawnerInfo {

  mob: string;
  /** Ticks until its next try. */
  delay: number;
  /** After a try that spawned something, the next comes minDelay..maxDelay ticks later (200..800). */
  minDelay: number; maxDelay: number;
  /** Tries per round (4). */
  count: number;
  /** It waits while this many of its mob are near it (6). */
  maxNearby: number;
  /** It only works with a player this close (16 blocks). */
  playerRange: number;
  /** How far from it creatures appear (4 blocks). */
  range: number;
}

    /** An item name, or an 18 x 18 cell of a 256 x 256 picture in the mod. */

  /** Give / take a skill, no cost. */

  /** y null: onto the ground there. Never into blocks or off the world. */

  /** Everything a player carries: slots 0-8 the hotbar, 9-35 the rest; armour head, chest, legs, feet. */

  /** Put items in one of a player's slots (0-35, or "head" / "chest" / "legs" / "feet"); item null empties it. */
  setSlot(player: Player | number, slot: number | 'head' | 'chest' | 'legs' | 'feet', item: Name | ItemStack | null, count?: number, data?: number): void;
  /** Take up to count of an item from a player (data: only that variant); how many were taken. */
  take(player: Player | number, item: Name, count?: number, data?: number): Promise<number>;
  /** Empty a player's inventory (armorToo: the armour as well). */
  clear(player: Player | number, armorToo?: boolean): void;
  /** "survival", "creative" or "challenge" (a 404 Challenge world: it stays). */
  gameMode(player: Player | number): Promise<'survival' | 'creative' | 'challenge' | null>;
  /** Their items come along. */
  setGameMode(player: Player | number, mode: 'survival' | 'creative'): void;
  /** An operator? The host always is; the host makes others ones with /op <name> (kept with the world). */
  isOp(player: Player | number): Promise<boolean>;
  /** The same from a script (the host's own scripts, or an operator's). */
  setOp(player: Player | number, on: boolean): void;
  /** What they play on and whether they're AFK (and for how long, in ms). */
  presence(player: Player | number): Promise<{ device: Device; afk: boolean; afkMs: number } | null>;
  /** Mark them AFK (until they're active again) or back (an "/afk" command...). The host's own

  setAfk(player: Player | number, on: boolean): void;
  /** Give them an achievement - the first time only (kept with the world): the "Achievement get!"

  award(player: Player | number, id: string, opts?: { name?: string; description?: string; icon?: Name }): void;
  /** Their achievements in this world, every mod's: {"<mod>:<id>": time earned (ms)}. */
  achievements(player: Player | number): Promise<{ [id: string]: number }>;

interface Menu {
  /** Open a menu again with the same id to update it. */
  id: string;
  /** false: a panel - beside the game instead of over it. No dimmed backdrop, the game keeps the
   *  mouse and keys everywhere else, several can be open at once (one per id). Place it with
   *  position and width / height in CSS pixels - client.on("screen") says where the game's
   *  inventory window is, to dock one beside it. No Close button unless closeButton: true. */
  modal?: boolean;
  /** A panel's place: {left | right, top | bottom} in CSS pixels. */
  position?: { left?: number; right?: number; top?: number; bottom?: number };
  /** A panel kept but out of sight (an html one keeps running); open it again without to show it. */
  hidden?: boolean;
  title?: string;
  /** In pixels, 200-720 (default 380). For an html menu: pixels or "80%". */
  width?: number | string;
  height?: number | string;
  elements?: Element[];
  style?: MenuStyle;
  /** Your own page instead of elements: "gui/shop.html" in the mod. It gets window.mcre and nothing
   *  else - no internet, no game page: data, send(x), on(fn), close(), touch, and
   *    icons(items) -> Promise [{item, data, id, name, max, icon}] (icon: a 32 x 32 picture URL),
   *    asset(path) -> Promise URL of one of the game's pictures ("font/default8.png"),
   *    panel (true for a panel), area(rects | null): only these parts [{x, y, width, height}] of a
   *    panel show and take the mouse - the game gets the rest. A panel hands the game the keys it
   *    doesn't type with (or preventDefault) and the mouse's movement. */
  html?: string;
  /** For an html menu: mcre.data; opening it again with the same id passes new data to mcre.on. */
  data?: any;
  /** false: no Close button (Esc still closes it). */
  closeButton?: boolean;
}

  | 'soundStyle';

   *  hopper), "creative", "station" (enchanting / anvil / brewing), "trading", "pause", "chat",
   *  "death", "sign", "bed", "menu" (no world), "other". */
  screen: string;

  rect: { x: number; y: number; width: number; height: number } | null;

  width: number; height: number; scale: number;
  /** The screen's close X, in CSS pixels (null: it has none). It is always on top: the game cuts

  close?: { x: number; y: number; width: number; height: number } | null;
}

  soundStyle(): Promise<'old' | 'new'>;

  setSoundStyle(style: 'old' | 'new'): void;

  /** true: clicks on the game's inventory slots are this mod's ("slotClick" decides). */
  captureSlots(on: boolean): void;
  /** What the game knows about an item. */
  itemInfo(item: Name | ItemStack): Promise<{ name: string; max: number; block: boolean; category: string; rarity: string; durability?: number; food?: number; armor?: string; id: number | null } | null>;
  /** The stack on the cursor of an open inventory screen (null: nothing). */

  setHeld(item: Name | ItemStack | null, count?: number, data?: number): Promise<boolean>;
  /** Every block and item the game has - variants and mods' included - in the creative
   *  inventory's order, each a full stack. */
  items(): Promise<ItemStack[]>;
  /** Kept on this device for this mod, in every world (settings a player chose, their favourites...). */
  storage: { get(key: string): any; set(key: string, value: any): void; all(): { [key: string]: any } };
}
